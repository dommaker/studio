# 频道消息数据层裁剪：降级而非释放（2026-08-25）

> 来源：#326 grilling（2026-08-25，维护者当场确认 Q1–Q8 全部推荐案）。
> 状态：**accepted**（待 #326 实施落地）。
> 前置：ADR 2026-08-24 channel-stream-virtualization（#325，渲染层 windowing 已落地）。

## 背景

#325 一期只动渲染层：virtualizer 决定 items 哪段进 DOM，但 `messages` 数据数组
随「加载更早」分页与 live 追加无界增长，JS 堆内存占用随频道总长线性增长。
内存大头 = 每条消息的 `content` 全文字符串与 `meta` 对象（后端出口已 JSON.parse，
含 cardData 等）。#325 ADR D3 明确本问题归 #326，且未预留任何释放/降级约定。

## 决策

### D1 形态：降级（骨架化），否决整段释放与分层混合

远离视口的上方历史消息**对象留在数组原位**，剥离 `content`/`meta`，只留结构字段
（id/createdAt/authorType/agentName/replyToId/workUnitId）+ `degraded` 标记 = 骨架；
渲染为固定小高度占位行。

- **否决整段释放**（区段移出数组留占位区间）：击穿三处全量数组语义——
  `groupIntoThreads` 归组（anchor 被释放则 replies 滞留主流）、已完成折叠计数
  （`completed.slice(-2)`/`completedCount`）、`messageToItemIndex` 锚点查找
  （锚行落入已释放区段时阅读位置恢复静默钉底）。每处修复都是一次锚点机制重设计，
  与内存收益不成比例。
- **否决分层混合**（近降级远释放）：同时背两套语义，一期不值。
- **否决骨架留摘要**（content 截断 ~80 字符）：占位行职责是「这里有未加载历史」，
  不是内容预览；摘要属增强，需要时后续票再加。

### D2 方向：只裁上方历史

下方是钉底/跟随/「回到底部」语义作用区，不裁。「用户长期停在历史中上部 + live
洪峰导致下方无界增长」为已知留白，真出现再开后续票。

### D3 触发：保底 + 视口距离 + 迟滞

最近 K 条永全量（钉底语义区），其外按「距视口上方超过 D 条」降级；降级阈值
D₁ > 水合阈值 D₂ 防边界抖动。K/D 为可调常量（初值 K=100、D₁=50），实测后调。

### D4 水合：整页水合，复用现有分页与归并

virtualizer range 进入降级区（防抖 ~200ms）→ 以降级区骨架 mid 为 `before` 游标调
现有分页接口（`queryMessagesPage` 穿透冷热归档，任意存在 id 可作锚点）→ `mergePage`
归并，骨架原位复活为全量。水合完成前占位行继续渲染。**否决按 mid 精确取**（需新增
后端端点，且 `getMessageById` 只读热文件）。

**唯一复活规则**：拿到全量本体的任何路径都原位复活——SSE `message_updated`
命中骨架同样原位整体替换，无特例。

### D5 阅读位置：粗锚/精锚分级

- 锚行全量 = **精锚**：`{mid, top}` 完整语义，两段式恢复（粗定位 + 像素级精校正）
  维持 #325 现状不变。
- 锚行是骨架 = **粗锚**：恢复 = 定位到该锚行 + 触发水合，不做像素级精校正；
  存档时锚行已是骨架同样存粗锚（`top` 以哨兵值表达）。占位行高上量出的 top
  对水合后行高在原理上无效，强行精校正必然错位。
- 语义下界严格优于现状：骨架锚行能承诺「回到那条消息」（现状锚行缺失时直接钉底）。

## 验收口径

字节口径：`messages` 数组内 `content`+`meta` 合计字节数有上界，不随频道总长增长
（骨架允许线性增长）。证据降档为开发期实测（studio 未投产）：#323 monitor/bench
手段或手动 profile 出一组长频道前后对比，以「增长曲线变平」为证，不建重型测量基建。

## Consequences

- 降级/水合只动 `useChannelMessages` 数据层 + 占位行渲染；`deriveStreamView` 管线
  语义零改动（结构字段全留是不变式）。
- 不变式：`mergePage` 轮询归并与 `channel.message_sent` 有序插入与骨架零互动
  （前者只碰底部最新页，后者插底部；reply 的 anchor 是骨架时 `replyToId` 仍在，
  归组不受影响）。
- 无新增依赖、无后端改动（D4 复用现有分页端点）。
- 已知留白：下方增长（D2）、骨架摘要（D1）、K/D 调参（D3）。

## 实施回写（2026-08-25，#326 P1–P4 落地 + code-review 两轴评审后）

1. **D1 修订：骨架保留 `meta` 的 `{status, cardType}` 标量子集**（实施期补定，维护者
   计划评审确认）。`deriveStreamView` 的 `isCompleted`（meta.status）与 `mergeable`
   （meta.cardType）依赖这两字段，全剥会使已完成折叠计数与连续合并判定失真
   （违反 AC「折叠计数一致」）。字节量可忽略，不改变字节口径验收。
2. **D5 修订：粗锚以 `coarse?: boolean` 字段表达**，不用 `top` 哨兵值——`top` 保持
   有效数字语义（粗锚存档同样记录捕获时偏移，备将来参考），显式布尔比哨兵值更
   不易误读；`parseReadingPosition` 向后兼容（缺省 = 精锚，非布尔忽略）。
3. **D4 补充：legacy `message_updated` patch（无全量本体）仅当携带 content 时复活
   骨架**——仅 meta 的 patch 不假复活（空正文渲染为全量行是缺陷形态）。
4. 水合并发守卫：in-flight 期间到达的水合触发重排（等落地后再取），不丢弃。
