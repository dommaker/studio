# 拆单（任务单 → 子工单）

把 spec 或已明确的需求结论拆成一组 **tracer-bullet 子工单**：每张票是一条窄而完整的纵切，声明自己的阻塞边。产出只进工单系统，不落任何文件。

---

## 集成

上游：**requirement-clarify**（spec 已过位2 质量门）或用户直接给定的明确方案。
产出：子工单（implement 类型），每张 = 端到端行为 + AC + Blocked by。
下游：**tdd-implement**（认领 frontier 票实现）。

---

## 硬门禁

<HARD-GATE>
产出 = 工单，不是文件。禁止落 task.md / plan.md / SDD 三层文档——拆单结果的唯一载体是工单系统。
拆单结果必须经人审粒度确认后才发布（Step ④）。
</HARD-GATE>

## 反模式：常见借口

| 借口 | 反驳 |
|------|------|
| "按层拆更清晰" | 横切层票（先 schema 再 API 再 UI）没有一张能独立验收。纵切才交付行为。 |
| "一张票做完更省事" | 塞不进一个上下文窗口的票 = 实现中途丢上下文 = 返工。 |
| "人审是走过场" | 粒度错觉是拆单最大的失败模式。人审一次 < 拆错重做。 |
| "工单里写清文件路径方便实现" | 路径会过期，工单长青。决策写进工单，定位留给实现者。 |

**危险信号**：
- 票名按技术层命名（"加表""写接口"）而不是按用户可感知行为命名
- 任何票无法独立演示/验证
- blocking 边连成一张网——多数边是"顺手"不是"门控"

## 执行流程

### ① 读取输入

从对话上下文工作。用户给了引用（spec 路径 / 工单号）→ 取全文读完。

### ② 探索代码库（可选）

未探索过则先探索：票标题与描述用项目领域词表（CONTEXT.md）词汇，尊重触及区域的 ADR。
留意 prefactor 机会："让改动容易，再做容易的改动"——prefactor 单独成票，排在最前。

### ③ 纵切草案

<vertical-slice-rules>

- 每票切一条窄而**完整**的通路，穿过所有层（schema、API、UI、测试）——纵切，不是某层的横切
- 完成的票可独立演示或验证
- 每票大小以单个全新上下文窗口能装下为限
- prefactor 先行，单独成票

</vertical-slice-rules>

给每票标 **blocking 边**：哪些票必须先完成它才能开始。无 blocker 的票可立即认领。只连真正门控的边，不连"顺手相关"。

**wide refactor 是纵切的例外。** wide refactor = 一个机械改动（改列名、改共享符号类型）的爆炸半径扇出全仓，单次提交打碎上千调用点，没有纵切能落绿。不要硬塞进 tracer bullet，走 **expand-contract**：

1. **expand**：新旧形态并存，什么都不破。
2. **migrate**：按爆炸半径分批迁移调用点（按包/按目录），每批一票、blocked by expand；旧形态还在，批批保绿。
3. **contract**：无调用方后删旧形态，blocked by 所有 migrate 批。

若分批也无法各自保绿，保留顺序但共享一条集成分支，全部 block 一张最终 integrate-and-verify 票——绿只在那里承诺。

### ④ 人审粒度

把拆单方案以编号列表呈现，每票给出：

- **标题**：短描述
- **Blocked by**：门控它的票（无则标"可立即认领"）
- **交付什么**：这票做成的端到端行为

问用户：

- 粒度对吗？（太粗 / 太细）
- blocking 边对吗？——每票只依赖真正门控它的票？
- 有该合并或再拆的票吗？

迭代到用户确认。**未确认不发布。**

### ⑤ 发布到工单系统

按依赖序发布（blocker 先建，子票才能引用真实单号）：

- **studio 自研**：GitHub sub-issue + 原生 blocking 边，操作约定见 `docs/agents/issue-tracker.md`
- **业务工程（平面2）**：PMO 子工单 + blocked_by 关系

每票用同一模板：

```markdown
## 做什么

<这票做成的端到端行为，用户视角——不是分层实现清单>

## 验收

- [ ] AC 1
- [ ] AC 2

## Blocked by

- #<n> / 无——可立即认领
```

工单里避免具体文件路径和代码片段（会过期）。例外：原型产出的片段比散文更精确地编码了决策（状态机、reducer、schema、类型形状）→ 内联并注明来自原型，只留决策密度高的部分。

不关闭、不修改父工单。

## 自检

自检修复最多 3 轮。超过仍未全过 → 停下报告，不发布。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 纵切 | 每票穿过所有层，可独立演示/验证 |
| 2 | 粒度 | 每票可装进单个上下文窗口 |
| 3 | blocking 边 | 只连真正门控的票；无环 |
| 4 | wide refactor | 已识别并走 expand-contract，未硬塞纵切 |
| 5 | 人审 | 粒度与边已经用户确认 |
| 6 | 载体 | 零文件产出，全部入工单系统 |
| 7 | 无占位符 | 工单无 TBD/待定；无易过期的文件路径（原型片段例外） |

## 终端状态

发布完成后报告：

1. 票清单（编号 + 标题 + blocking 边）
2. **frontier**：无 blocker、可立即认领的票

派单/认领流转由机制承载，本 skill 到此为止。
