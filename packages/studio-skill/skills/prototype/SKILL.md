# 原型（analysis 工单方法论）

蓝本 matt 同名 skill；产出契约改指系统载体（T3/#125）。原型是**回答一个问题的一次性代码**——问题决定形态。**仅用于纸面裁不动的设计问题**：能在讨论中定的事直接定，别造代码。

## 选分支

先识别在回答哪类问题——从工单正文、周边代码判断，歧义且人类可达就问：

- **「这套逻辑/状态模型对吗？」** → [LOGIC.md](LOGIC.md)。单个可分享 HTML 文件——自由按钮 + 分页签的引导走查——把状态机推过纸面上推不动的用例，非开发者也能点。
- **「该长什么样？」** → [UI.md](UI.md)。同一路由上出几个**结构上截然不同**的 UI 变体，URL search param + 浮动底栏切换。

两个分支产物形态完全不同，选错 = 整个原型白做。问题真歧义且人类不可达：按周边代码默认（后端模块 → logic；页面/组件 → UI），并在原型顶部声明这个假设。

## 两分支通用规则

1. **从第一天起就是一次性的，并明显标记。** 原型代码放在它实际服务的位置附近（被原型的模块/页面旁边），上下文自明；命名要让路人一眼看出是原型不是生产代码。一次性 UI 路由遵守项目既有路由约定，不自创顶层结构。
2. **跑起来零门槛。** UI 原型从项目任务 runner 一条命令起；逻辑 demo 是双击即开的单 HTML 文件。
3. **默认无持久化。** 状态驻内存。除非问题本身就是持久化——那时用 scratch DB 或明确命名「PROTOTYPE — wipe me」的本地文件。
4. **不打磨。** 无测试、只保留能跑的错误处理、无抽象。目的是快速学到东西。
5. **状态外显。** 每次动作（logic）或变体切换（UI）后，完整渲染相关状态，让人看见变了什么。
6. **完工即捕获。** 验证过的结论折进真实代码；原型本身作为**一手来源**捕获：提交到一次性分支，留指针。

## 产出契约

- 一次性代码落 **`prototype/<name>` 分支**——**不合并、不进评审**（master 只保留验证过的结论）。
- **结论记录**：在来源工单写清回答了什么问题、答案是什么、原型分支指针。
- 后续工单经 `blocked_by` 挂图依赖本原型时，引用工单结论 + 分支名，不是会话记录。

## 约束

- token 预算熔断适用（T8 通用能力，#130）：原型建造受预算约束，耗尽即停并汇报已验证/未验证的部分。
- 一个原型回答一个问题；问题多了拆工单，不在一个原型里摊大饼。
