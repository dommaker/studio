# packages/studio-shared

### 职责

跨 apps/packages 的共享层：provider 注册表（agent CLI 定义与 spawn 模板）、FileStore（全部运行时数据的文件存储）、eventBus、共享类型与工具、 harness 运行时。Node-only 能力经 `@dommaker/studio-shared/node` 子路径导出（读 fs，前端不可引）。

### 约束

- **F6 派生口径铁律**：WU 状态/证据的所有展示与指标只准调 `deriveDisplayState()`（src/attestation.ts），禁止 UI/API/指标各自读 `metadata.attestations` 自行解释——口径分叉 = 可读性崩坏。改派生规则只能改这一个函数。
- **WorkUnit 写路径铁律（#170，决策 #65）**：events/index 写必须经锁内复合原语——快照写走 `commitSnapshot`（事件+索引同锁成对，禁止锁外分两步），删除走 `commitRemoval`（必须落 closed+deleted 墓碑，否则对账/重建会复活已删 WU），metadata 增量写走 `updateMetadata`（mutator 基于锁内最新值，禁止读时快照全量回写），带前置条件的建单走 `createSnapshotGuarded`。
- **审计数据落点铁律（#590，ADR 2026-09-17 决策 3）**：一次性决策事件禁止写入 KnowledgeStore——耐久知识库不放事件流。审计数据唯一归宿 = apps/api `audit-logs` 轨（FileStore + 现有审计页/查询/导出/鉴权）；补 agent 自主决策埋点走该轨并加 `actorType: agent` 维度，不在本包重建事件发布器、不新开第三条轨。判据与 A/B 类补齐方案见该 ADR。

### 注意事项

- **类型消费走 dist**：package.json `types` 指向 `dist/*.d.ts`（runtime 入口才是 src），改本包类型后须 `pnpm --filter @dommaker/studio-shared build` 重建 dist，否则下游 tsc-gate 报 TS2339（新字段不可见）。
- **execSh 受控执行选项（SEC-01）**：默认仍继承 process.env；`inheritProcessEnv:false` 时只传显式 `env` 白名单。`maxBuffer` 约束 stdout 与 stderr 的合计 UTF-8 字节数，超限杀进程并保留原 stdout/stderr 错误前缀；core/host-execution-policy 另叠加进程组 kill、固定超时和白名单 env。
- **Agent 允许/拒绝矩阵（SEC-05，2026-10-27）**：OS 身份固定 uid/gid/groups=65534，禁止 root supplementary group；worktree 权限采用快照策略——预备时仅把既有 uid 保留、gid 改为 65534 并给 group 写（含 `.git`），dispose/初始化失败恢复原 uid/gid/mode，新文件保留 gid 65534，禁止无恢复递归改权。文件仅 worktree 可写，系统运行库、TLS、当前 provider 安装、真实 harness shim 及其生产依赖闭包、必要凭证只读，其他宿主路径默认不存在。网络断直连，只允许经 per-run Unix-socket broker 访问 provider API、npm/GitHub、Studio 回调及 Operator 显式配置的 host+port；loopback/Studio 目的地的 plain HTTP 由 broker 覆盖写入独立 `sab_` 来源标记（不发往外部主机，防反射泄露），loopback/Studio callback 的 CONNECT 一律拒绝，Agent 不能靠省略或更换 bearer 逃离执行面。secret 通道只注入当前 provider allowlist env/只读凭证和 per-execution `sta_` 回调 token，Deploy/JWT/Admin/通知秘密不进入沙箱。identity 签发后任一初始化失败都回滚 token、server、socket 目录与权限；dispose 幂等。非 Linux/非 root 无等效边界时 fail-closed。长期 provider token/OAuth 仍可在允许的 API 目的地重放/消耗额度，未宣称短期化。测试用假 secret + 临时目录 + 本地 HTTP 服务及真实 shim，覆盖秘密不泄漏和越界文件/网络/API 零副作用。
- **对 harness 约束面的消费很薄，升版时别按"重度集成"排查**（2026-09-24 采纳 harness 1.14.0 逐条判读的落点）：本包只在 `src/index.ts` / `src/node.ts` 重导出 `ConstraintResult` 类型，**全仓无一处运行期读 `skipped`/`skipReason`**（唯一相近消费点 `safety.tools.ts` 按 `!satisfied` 过滤，skip 恒 `satisfied=true`，语义与旧版一致）；生效集由 harness builtin 7 条提供，studio 无 `.harness/constraints.yml`。故 harness 侧改判定接缝形状（`boolean | 'skip' | CheckSkip{skip,reason} | CheckDetail`）或引入 `channel` 字段（缺省 gate、注册表闭环只收 gate 条目）时，studio 默认无恙，**但要拿被改仓的真实 diff 回放新旧两版对跑才有信号**——`harness check` 缺省面在干净树上只分发两三条约束，跳过清单这类路径在常规触发面上根本观测不到。
- **harness 升版的隐性必踩点：`harness init` 重写 config.yml（harness#210，4.0.1 起修复）**：仓根 `package.json` 的 postinstall + prepare 双挂 `scripts/harness-sync.js`（全仓唯一 `npx harness init` 调用方，裸跑无 flag）——`node_modules` 实装版 ≠ `.harness/config.yml` 的 `harness.version` 就触发 init。4.0.0 及之前 init 全量重写该文件，把 `governance.context_files.required_dirs`（AUTO-GENERATED 段，正本 `pnpm gen:required-dirs`）连 YAML 注释一起冲掉（注释经 `yaml.dump` 永不回写），随后 `gen-required-dirs` 因缺标记段直接报错；4.0.1 改读旧文件深合并、保留非受管键。两条连带纪律：① 升版走 `studio-harness-upgrade`——其第 3.6 步把版本戳一并改到目标版，正是该文件不挂脏 diff 的原因；② 模块整拆后必须重跑 `pnpm gen:required-dirs`，否则清单里那个已删目录会被 init 补一个 CONTEXT.md 骨架，连带 `harness sync-docs` 把 AGENTS.md 对应模块行降级成骨架占位句（实测：批6 `4f971836` 删 admin 模块 → 未重跑生成器 → 下一次 install 补骨架 + AGENTS.md 行变「请阅读本目录源代码」）。
- **测试 /tmp 泄漏防护正本（2026-08-26）**：`tests/mkdtemp-cleanup-setup.ts` 是 packages 侧唯一正本，经各自 `vitest.config.ts` setupFiles 接入（studio-skill/notification/agent 跨包引用本文件，不存副本）。机制：patch `fs.mkdtempSync` 登记 + 文件级 afterAll 清理 + import 时清扫 >24h 签名残留；机制自测在 `tests/__tests__/mkdtemp-cleanup-setup.test.ts`。盲区：测试文件 `import * as fs` 走原生冻结命名空间绕过补丁，此类文件须自带显式清理（同 apps/api/tests/mkdtemp-cleanup.ts 头注）。
- **FileStore 目录布局**（`~/.studio/data/`）：`agents/{id}/profile.json` + `agents/{id}/state.json`（Agent 身份与运行时实例，共享同一目录 namespace）；channels/workunits 等同理按域分目录。其他相关路径：`~/.studio/providers.json`（provider 覆盖）、`~/.studio/workspaces/{id}.json`（workspace 记录，内嵌 runtimes）。**数据区布局唯一正本 = `docs/architecture/data-directory-contract.md`（#570，2026-09-16 冻结），布局变更须先修订契约。**
- **实例目录生命周期闭环（#363，2026-08-26）**：历史死实例只删 state.json 不删目录 → `agents/` 下空目录无界累积（实测 753 目录里 735 是空的，`listStates`/`listProfiles` 每轮空扫全部目录）。闭环三件：① `deleteState` 删 state.json 后判空删目录——目录为空才 rmdir，有 profile.json 或任何其他文件绝不碰（共享 namespace）；② `sweepEmptyAgentDirs()` 一次性存量清扫（同判空条件，幂等，挂载点 = apps/api index.ts 启动段）；③ terminated 实例回收统一归 instance-timeout-scan（apps/api 侧，每 5min 跨角色），agent-loop 的同角色启动清理已拆除。
- provider 注册表是"装了哪些 CLI"的唯一权威定义：daemon 扫描（`apps/api/src/daemon/cli-scanner.ts`）、本地扫描（`local-workspace.ts`）、spawn（`cli-adapter.ts`）、健康探针（`agent-loop.ts`）全部从这里取定义，新增 CLI 只需 `~/.studio/providers.json`。
- FileStore 写操作全部原子写（tmp+rename），跨进程并发经 `withLock()`（mkdir 锁）。
- **读穿缓存 seam（工单 26 A1 + #321 扩展）**：`jsonCache`/`jsonlCache`/`dirCache`/`mdCache` 四个模块级缓存（按绝对路径 key，mtimeMs 校验，跨进程外部写靠 mtime 兜底失效；命中返回结构克隆）。`readDoc`/`readDocWithMtime`（#321：markdown frontmatter+body，后者带校验用 mtimeMs 供调用方兜底链复用同一次 stat）与公开 `readdir`（目录 mtime 校验，ENOENT 抛错语义同 fs）都住这个 seam——聚合只读层（library、sdd-legacy）读外部仓走这里，不得再裸 `fs`。写路径（`writeJson`/`writeDoc`/`appendJsonl` 等）经 `invalidateFileKey` 精确失效 + 清 dirCache。**例外：锁内读保持裸读（#314 D1，ADR 2026-08-24-cache-seam-decision-rules 例外条款），给锁外路径加缓存时不得顺手换掉锁内读。门面 `readJsonUncached` 直接委托 FileStoreBase，专供锁内/跨进程实时 RMW；普通查询继续用 `readJson`。**
- **Markdown 文档路径安全（SEC-04，2026-10-26）**：`readDoc`/`readDocWithMtime`/`writeDoc`/`deleteDoc` 只接受单段 key，统一拒绝绝对路径、两种分隔符及 `..`，并校验 resolve 后不离开 `dir`。读写在 Linux 上通过 `/proc/${process.pid}/fd` 固定已校验真实父目录（Git 子进程也能访问父 fd），最终文件 `O_NOFOLLOW` 打开；读使用同一 fd 的 fstat/mtime 与内容，缓存命中也不能跳过安全检查。写入缺目录逐级 no-follow 创建，内容先写同目录 `O_EXCL` 临时文件再原子 rename，失败清理且不截断原文。删除在固定父目录内做最终 no-follow 核对后直接 unlink；unlink 本身不跟随 symlink，不承诺目标身份不变。legacy SDD 改为 `dir=<base>/<slug>, key=<layer>`，不在 key 中携带 `/`。`directory-capability.ts` 经 `/node` 导出 `withDirectoryCapability`，供实际执行回调持 fd。
- **频道消息存储（#319，2026-08-24）**：`channels/{id}/messages.jsonl` append-only + tombstone，编辑 = 同 id 追加新版。写侧压实：`appendMessage`/`softDeleteMessage` 走 per-channel `messages.lock` 互斥（防压实重写与并发写竞争丢行），每 500 次写评估一次，总行数 ≥5000 且死行占比 ≥30% 时把活消息（每 id 最新版、首现位置序，口径同 `resolveActiveMessages`）原子重写回文件——只清死行不动活消息，阈值可经 `FileStoreOptions.messageCompaction` 注入（测试用小阈值）。新鲜度契约（§4.2）以消息 id 为锚：`getChannelVersion()` 只返回 `lastMessageId`（行号口径已退役——压实会压缩行数），`getMessagesSince(channelId, messageId)` 取锚点后增量；锚点行被压实抹除时保守返回全部活消息（有界误报，绝不漏报）。分页下沉：`queryMessagesPage(channelId, { before: 消息id, limit })` 在存储层切片，`before` 锚点不存在时返回空页不整页错发。**热层倒扫快径（2026-09-16 channel 体检 B4/B5）**：before 锚在热层时倒扫到锚再多收 limit+1 条即停（不再每页全量 resolve+sort+findIndex；锚穷举未命中直走冷链锚路径），带过滤 + limit 的 `queryMessages` 走 `readMessagesTail` 谓词倒扫早停（无 limit 的带过滤查询保持全量路径）；#576：`QueryOpts` 增 `before`（ISO，createdAt 严格 <，与 `since` 的 >= 互补），快径谓词与全量路径 filter 逐句同口径，供 WU 讨论串 limit 下推；两条快径都以「窗口 createdAt 严格递减 + 锚前活跃消息 createdAt 全 > 锚点」为出页判据，违例（等 ts 撞车/病态副本交织）回退全量路径保精确，测试在 `__tests__/file-store-hot-scan.test.ts`（含扫描行数上界断言）。
- **频道消息生命周期归档（#327，2026-08-25）**：热/冷两层——热 = `messages.jsonl`，冷 = `archive/messages-YYYY-MM.jsonl`（超龄消息按消息 createdAt 归月，纯 `ChannelMessageData` 行无 tombstone、月内升序）。`archiveChannelMessages()` sweep（挂载点 = apps/api index.ts 轮转调度：启动一次 + 每 24h）：逐频道 `messages.lock` 锁内裸读热文件 → `mergeActiveRows` 归并（顺带压实，同口径）→ 按计龄锚点分区：有 workUnitId 看所属 WU `closedAt` + 30 天（遗产 closedAt 缺失回退 `updatedAt`；WU 悬空回退 createdAt 规则；WU 非 closed 一律保留），无 workUnitId 看自身 `createdAt` + 30 天；写序先冷后热（冷侧追加前按 id 去重吸收崩溃残留，热原子重写）；无超龄不重写热文件；配置 `FileStoreOptions.messageArchive = { maxAgeDays?, now? }`（仿 messageCompaction 注入模式）。`thawWorkUnitMessages(workUnitId)` reopen 解冻：全频道扫 archive/，该 WU 冷行 append 回热（保留原 id/createdAt，热侧已有同 id 不重复）→ 冷文件原子重写剔除；无 archive 目录/无匹配行零成本短路。查询面：`queryAllMessages`/`getMessageById`/`listByWorkUnitId`/`countMessages`/observe 全部热只读（冷数据默认不可见）；仅 `queryMessagesPage` 穿透冷热——遍历链 = 热（新→旧）接冷（月新→旧、月内 createdAt 新→旧），无 before 时热页不足 limit 从冷链补满（热全空时首页直接出冷，滚动穿透历史永远在）、锚在热不足余量从冷续、锚在冷整页从冷出、冷热都没有 → 空页 + hasMore=false（#319 契约不动），跨冷热同 id 新→旧先见为准（热遮蔽冷侧 thaw/崩溃残留）。`WorkUnitSnapshot.closedAt?` 是计龄锚点字段（可选，旧快照兼容；关闭路径写入、reopen 清除，写入点见 workunit 模块 CONTEXT.md）。
- **PERF-02 WU 当前态投影（2026-10-29）**：`workunits/current/<sha256-id>.json` 保存 per-WU snapshot，`current/heads/<sha256-id>.json` 保存该 WU 的完整提交 head（byte offset + dev:ino），二者必须精确一致；`current/manifest.json` 保存全局提交 head + projection 文件数。正常事件写同锁按 events → append-only index → projection/head → manifest；legacy upsert/remove 无 events 直写先在 index 前追加 `current/legacy-pending.json`，随后走增量 finalize，成功后清除，不做全量 replace。统一 `recoverLegacyPendingLocked` 在 ensure/rebuild/reconcile/append 最先从当前 index fold 恢复，replace 全程保留 pending；rebuild/reconcile 安全返回恢复结果，appendEvent 恢复后 fail-closed 零事件并改走 commitSnapshot。锁内 claim/updateMetadata/lease flush 只裸读目标 projection/head + 全局 manifest，guarded create 枚举当前 projection，均不 fold 历史 index、不用 mtime cache。其他失配/缺失/损坏从 events 重建；events 半行 fail-closed 零副作用，截断未提交半行后恢复。数据布局 v3 与协议正本见 data-directory-contract。
