# packages/studio-shared/src

### 职责

本目录是 Agent-Studio 的前后端共享库，提供配置管理、常量定义、事件总线与文件存储等通用基础设施，为 apps/api 等多个上层模块提供复用的工具与类型。

### 注意事项

- `providers.ts` codex spawn 模板带安全基线 `CODEX_SAFETY_CONFIG_ARGS`（2026-09-22，codex 0.154.0 实测）：`-c` 覆盖 workspace-write 沙箱 + `sandbox_workspace_write.network_access=true` + 包管理器缓存目录 writable_roots。baseArgs/resumeArgs 两路同带；providers.json 用户覆盖是整数组替换，覆盖即接管安全基线。SEC-05 起 network_access 只放开 Codex 内层沙箱，实际目的地仍受外层 per-run egress broker host+port allowlist 限制；原内层 `shell_environment_policy.inherit="core"` 删除，避免剥掉 broker 代理变量，秘密过滤统一由外层 `buildProviderSpawnEnv` 承担。
- **SEC-05 共享边界**：`providers.ts buildProviderSpawnEnv`、`utils/agent-sandbox.ts` 与 `utils/agent-identity.ts` 是 runner/SystemExecutor 唯一执行隔离组合；禁止调用方退回完整 env 或无 sandbox 的 `execSh`。Agent 来源以 broker 写入的独立 `sab_` 标记判定，不以 bearer 形状或 loopback 判定；`sta_` 仍用于 callback 鉴权且 executionId 必填恒等。真实 harness 包和生产依赖闭包只读挂载，非 fake shim 的允许/block 行为由 `utils/__tests__/agent-sandbox.test.ts` 验证。权限快照恢复、初始化回滚和 provider 长期凭证残余风险见包根 `CONTEXT.md`。
- `llm/stream-json-parser.ts`（#564，2026-09-16）：`StreamEvent.parent_tool_use_id` 是子 agent（Task/subagent）子树事件标记——CLI 对子树事件回填 Task tool_use 的 id，父 run 顶层事件为 null/缺省；`extractResult`/`extractUsage` 据此过滤子树（子 error result 不误杀父 run、usage 不父子双计），assistant 文本与 tool_use 提取不做过滤。#602 D4：`extractToolCalls` 配对 tool_use/tool_result（tool_use_id）得出 `ToolCall.success` 真实成败，无配对 → undefined（未知不编造）
- 本包 `@types/node` 钉在 20.0.0（泛型前的 Buffer 类型），与 TS 5.7+ lib 的 `ArrayBufferView` 泛型不兼容——`handle.read(buffer)` / `Buffer.concat` 传 Buffer 会报类型错，解法 = 传参处 `as Uint8Array`（Buffer 运行时即 Uint8Array 子类，纯类型层适配，参照 jsonl-tail.ts）；根治 = 对齐 apps/api 的 ^20.12.7（未做，另议）

- **SEC-07 文件权限**：`FileStoreBase` JSON/JSONL 写入目录强制 0700、文件 0600，写后 `FileHandle.chmod`（fchmod）不依赖 umask；`repairFilePermissions` 同时接锁内裸读与 `CachedFileIo` 公共 readJson/readJsonl，cache miss 和 cache hit 都修复历史宽松权限，mtime 缓存与结构克隆语义不变。回归 = `__tests__/file-store-base.test.ts` 的 Base 与公共 FileStore umask 022 用例。
- 配置优先级：环境变量 > `~/.studio/config.env` > 默认值，且仅当环境变量未设置时才加载 config.env
- **logger 双轨（P2.5，2026-10-16）**：pino 正本在 `utils/logger-node.ts`，仅经 `/node` 子路径出口导出（`node.ts` 显式导出覆盖 `utils/index` 星号导出的 console 版）；apps/api 全部 Node 侧消费方与 studio-agent 均引 `/node` 出口（pino-pretty 格式）。根入口的 console 版 `utils/logger.ts` 只保留给 web 可达模块内部用（file-store-base、studio-events）+ `Logger` 类型，勿把 pino 引进根入口 import 图。类型是 `Logger & pino.Logger` 交集：`(msg, meta)` 与 pino 结构化 `(obj, msg)` 两种调用形态都过类型检查，运行时是裸 pino 实例
