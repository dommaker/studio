# apps/api/src/modules/channels

### 职责

Channel 域：频道 CRUD/成员/路由表、消息创建与路由（replyTo 线程 / @mention 派单 / 决策12 默认角色）、情境引导建议推导、@文件引用词表、「当前 PMO」派生。

需求主入口已不在本模块：@Analyst 管线（scout/synth、RequirementsDoc、ContractTest、产卡自动执行）已于 2026-07-08（658ac7ae）整体删除；现实链路 = PMO `publish` 建 plan WU（pmo/project.service）→ plan 内 TASK 拆分经 `pmo/analysis-handoff` 建 task 子单 → `agents/loop/review-dispatcher` 派评审。

### 注意事项

- **频道图片附件（2026-09，docs/plans/2026-09-channel-attachments.md）**：`POST /:id/attachments`（requireAuth+requireNotGuest，与发消息同语义）收 JSON base64（不引 multipart 依赖），单图 ≤5MB 超限 413，落盘 `STUDIO_DATA_DIR/attachments/<channelId>/<uuid>.<ext>`（扩展名白名单 png/jpg/gif/webp，与 FileStore baseDir 同口径解析数据根）；返回相对 URL，消息体直接存 markdown 图片语法即完整事实源——**无附件元数据表**（YAGNI，mime 由 id 内嵌扩展名推导）。`GET /:id/attachments/:attachmentId` 经 `?token=` 携带 JWT（`tokenQueryToHeader` 映射进 header 复用 requireAuth；<img> 无法带 Authorization 头，SSE /events/stream 同款），guest session（userId=null）过不了 session→user 联查 = 看不了图（已知取舍，图比消息早一步要登录；2026-09-14 起消息 GET 同样要登录）。json limit：全局 2mb 不动，app.ts 在全局 parser 前对该路径预挂 `express.json({limit:'8mb'})`（已解析请求 `_body` 标记跳过全局），路由级同挂保直挂测试自足
- **输出文件路径**：`perInvocationOutputFile()` 返回绝对路径（ANALYST_DIR 基于 REPO_DIR）。scout 路径用相对路径，session-manager 有 worktree fallback
- **JSON 解析链**：4 层（sanitize → code-fence → regex → LLM repair），outputText = "DONE" 无 JSON，文件是唯一数据载体
- **DB 去重**：同 channel 24h 内有有效 RequirementsDoc → 直接复用（0 token）
- **outputFile 唯一性**：Claude 通过 Write tool 写文件，stdout 只有 "DONE"。文件丢失 = 数据丢失
- **鉴权分层（2026-09-14 起读写对称，推翻 2026-07-24 姿态 A 的「围观匿名公开」）**：全部 GET 读端点（`/`、`/:id`、`/:id/messages`、`/:id/suggestions`、`/:id/current-pmo`、`/:id/file-vocabulary`）挂 `requireAuth()`（读侧同样返回频道全量消息/成员/词表，与写侧对称；回归测试 `__tests__/channel.routes.test.ts` 锁匿名 401）；`/channels` 已移出 app.ts PUBLIC_API 白名单（前缀放行覆盖全部子路径）。9 条写端点（建频道/发消息/删频道/archive/restore/PATCH/members/convert-to-task×2）= `requireAuth()+requireNotGuest()`（card-decision 端点 #356 起随 auditor_suggestion 卡接线 review-proposal 正本而删）。注意 `POST /:id/messages` 经 @mention 派单/恢复挂起 WU 可直接触发 agent 执行与 LLM 消耗，是收紧前最危险的匿名入口。requirements-docs PUT 同为 requireNotGuest
- **apiCache 写后失效（#448，2026-09-02）**：`GET /` 挂 30s apiCache，频道记录写端点（POST `/`、PATCH `/:id`、PATCH `/:id/members`、DELETE `/:id`、PUT archive/restore）成功后 `clearCache(req.baseUrl)` 失效列表缓存——缓存 key 含 baseUrl（api-cache.ts `generateCacheKey`），按挂载点前缀精确清除；`POST /:id/messages` 等不改频道记录的端点不清（高频消息保持缓存有效）
- **消息路由优先级**（`message-routing.ts` routeMessage）：`replyToId` 线程回复（继承父消息 workUnitId；**#327 起父消息不在热层——已归档/不存在不可区分——降级放行**：帖子成立、replyToId 保留、workUnitId 继承失效落 null、不整帖抛错）→ `@mention` 派单（建 WorkUnit，`metadata.creationMode='mention'`；§9.5 只匹配本频道 members，members 为空回退全量 active profile）→ 纯文本仅存储。mention = 纯文本 `@name`（无结构化 id），检测与 scope 剥离用 Unicode 正则 `[\p{L}\p{N}_-]+/u`；手打中文连写无空格（`@开发你好`）由 **#496 前缀兜底**兜住——token 精确匹配失败时对成员名做最长前缀匹配（互为前缀取最长，等长歧义/同名 profile 并列回退未匹配现状），命中后 scope 只剥 `@成员名` 保留连写剩余文本，`metadata.mentionName` 落解析后正名；studio 系统角色不参与前缀兜底。归属解析出 PMO 项目时创建期落 `metadata.pmoId`（2026-08 归因统一 canonical key；原 `ownershipProjectId` 废弃不再写入，读取侧同级兼容）。**#464 出声**：@mention 未匹配（角色不存在/非本频道成员；@studio 无默认入口）→ 线程回「未找到角色/未配置入口，已转自动认领」系统消息（此前 WU 照建但频道零提示）；无归属挂起提问带 milestone（atHuman 响铃 + 行动中心通知）。**#494 派单原子性**：mention/决策12 两派单路径先落派发消息再建 WU，`metadata.anchorMessageId` 显式携带派发消息 id（认领播报优先锚它，消 created 事件先于派发消息落库的 findAnchorMessage 竞态），建单后 `linkWorkUnit` 回填消息 ↔ WU 关联（best-effort，同 createFromMessage 路径）。**#495 决策12 合并窗口（方案 a）**：defaultProfileId 派单前先查合并目标（**#524 P1-1 起查法 = `readMessagesTail` 尾部倒扫收集 20 条 human**，替代全热文件读，#514 D 方案）——同频道最近一条携带 workUnitId 的人类消息在窗口内（默认 5 分钟，`STUDIO_CHANNEL_MERGE_WINDOW_MINUTES` 覆盖）且 WU 在途（pending/unassigned/active/blocked）→ 消息并入该 WU 线程（replyToId=anchorMessageId，workUnitId=该 WU）不新建；blocked 经 resumeWaitingWorkUnit 复活注入，其余状态锁内追加 `metadata.pendingReplies`（loop 下一步 prompt-composer 注入）。窗口外/终态（done/closed/in_review）/@mention 照章新建。合并消息自身携带 workUnitId → 滑动窗口（连发 N 条 = 1 张单）。合并目标 metadata 解析走 `parseWuMetadata` 容错口径（畸形 JSON 落 {}、anchorMessageId 缺省走首根回退），不抛错拖垮整道路由。**#525 P2-2（2026-09-12，#517 项③）**：POST 路由层 404 判定已读的 channel 经 `options.channel` 传进 routeMessage（mention/决策12 两路径及 resolveWorkspaceForWU 不再重复 `getChannel`；未传入保持现状读——既有直调测试不走路由层）
